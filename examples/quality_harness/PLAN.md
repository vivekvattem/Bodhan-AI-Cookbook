# Translation and Speech Quality Harness plan

The headless digit proof and the 10-row offline execution milestone are implemented. The [README](README.md) describes the available checks and how to run them. The architecture below describes the target for the remaining assignment stages.

## Required interface

```bash
python -m bodhan_eval \
  --dataset path/to/data.jsonl \
  --langs hi,ta,bn \
  --out ./report \
  [--generate] [--baseline ./previous_report] [--calibration labels.jsonl] [--max-cost-inr 50]
```

The CLI reads UTF-8 JSONL with one object per line. The required fields are `id`, `source` (English), and `lang`. Optional fields are `reference`, `translation`, `audio`, and `labels`. The assignment's inline label example is `{"type":"number","severity":"major","span":[14,20]}`. With `--generate`, fill missing translations and audio through Bodhan while preserving supplied artifacts. With the flag omitted, evaluate supplied outputs, including Bodhan round trips used as checks. Count invalid rows, missing inputs, and unavailable checks, and continue evaluating usable fields. Resolve local audio paths relative to the dataset as a provisional default.

The demo covers Hindi, Tamil, and Bengali. `--langs` accepts all 13 production codes: `en,hi,bn,mr,te,ta,gu,kn,ml,or,pa,as,ur`. Use a language and voice registry and test at least one non-demo script through the same path. [Indic-Speak model card](https://huggingface.co/bodhan-ai/indic-speak#languages-supported)

| Required file | Acceptance check |
| --- | --- |
| `summary.md` | Headlines, coverage and skips, top failures, original evaluation cost, missed demo targets and reasons, and regressions when a baseline is provided. |
| `summary.json` | Metrics by language and category with denominators, coverage, and stable cost accounting. |
| `items.jsonl` | Per-item check statuses and flags with category, severity, original-text span or audio interval, and evidence. |
| `calibration.json` | Precision and recall by category for individual checks, judge, and combined verdicts, with support and thresholds. State when human labels are unavailable. |
| `diff.md` | Written only with `--baseline`. Match `(id, lang)` and compare findings within matched items. Include improved, regressed, and severity-changed examples and coverage changes. Missing evidence cannot resolve a prior flag. |

## Proposed architecture

The CLI validates and filters the dataset, builds a batch of allowlisted detection input, runs the bundled JSON graph in process with LFX, then calls `calibrate` and `report`. Langflow owns the order and conditional edges. Python owns the work inside each stage. Use `langflow==1.13.2` for optional visual authoring and `lfx==1.13.2` for execution. LFX removes the need for a server and additional runtime credentials. Under `src/bodhan_eval/`, shared `models`, `cache`, and `budget` modules own API calls, persisted responses, and cost admission. Each component should translate its ports to module arguments, delegate, and return structured results. [LFX compatibility](https://docs.langflow.org/lfx-compatibility) · [Pinned Python loader](https://github.com/langflow-ai/langflow/blob/v1.13.2/src/lfx/src/lfx/load/load.py) · [Custom components](https://docs.langflow.org/components-custom-components)

| Visible flow node | Python responsibility and acceptance check |
| --- | --- |
| Prepare supplied or generated outputs | `dataset` and `models` fill requested gaps and carry forward partial statuses. A mixed fixture verifies generation on and off and preserves supplied artifacts. |
| Run cheap checks | `text` maps normalized text to original offsets. `checks` score chrF++ where applicable, compare numbers, units, terms, entities, script and untranslated text, check Markdown, tables and LaTeX, and measure audio duration, silence, and clipping. Give every deterministic rule a clean control and a failing fixture. |
| Collect round-trip evidence | `models` and `checks` back-translate to English and back-transcribe eligible audio, then align expected text and transcript for omissions, truncation, and repetition. Waveform intervals support garbled-audio findings. If audio lacks trustworthy expected text, retain acoustic checks and mark text comparison unavailable. |
| Judge and plan follow-up | `judge` checks original source and target for omission, addition, mistranslation and other translation categories. It can corroborate speech candidates from text and acoustic evidence, or abstain. The rubric defines severity by user impact and requires an original anchor and English evidence. Candidate anchors must resolve locally before they are accepted. A Python policy combines ambiguity and risk with a stable audit sample to produce a bounded list of requests. |
| Route to follow-up or skip | The graph visibly branches on whether any follow-ups were approved. The follow-up node runs only the selected requests, such as a second transcription window for a disputed omission. The skip path records why work was skipped. Prove both branches and their convergence with call-count assertions. [Langflow conditional routing](https://docs.langflow.org/if-else) |
| Finalize evidence | Python combines and deduplicates corroborated candidates and retains inconclusive states. A checker-only discrepancy can remain inconclusive. Test clean translation paraphrases, legitimate code-mixing, and ASR hallucinations on otherwise clean audio. |

Keep an immutable copy of text. Comparison copies carry reversible character ranges across normalization, tokenization, and alignment. Propose half-open Unicode code-point offsets into named original fields. Use a source span for omitted translation content, a target span for added text, and an expected speech-text span for omissions where available. Use time intervals for waveform evidence. Tests must recover the exact original slice across digit folding, combining marks, whitespace, punctuation, repeated phrases, and Urdu script.

`dataset` separates labels and injection records before building the graph input. Checks, prompts, and sampling use allowlisted content and evidence. Identifiers remain join keys outside prompts and routing features. `inject` applies seeded programmatic text and audio edits or perturbs English and calls Indic-Translate. `calibrate` joins labels after evidence is collected, fits a small shared set of thresholds, and measures held-out precision and recall. Group clean and injected variants of the same source when splitting. Tag human annotations we add, distinguish explicit clean labels from absent labels, and report sparse support. Verify that changing only labels or injection metadata leaves detection requests and candidates identical.

## Verified upstream rules

- Hosted translation and back-translation use Indic-Translate. Prefer `POST /translate` for its documented translation, truncation, and token-usage fields. Bodhan also offers a compatible chat route. Synthesis uses `POST /v1/audio/speech` with `indic-speak`, a voice, and JSON-string `instructions` containing `lang`. Recognition uses `POST /v1/audio/transcriptions` with `indic-transcribe`, a language code, and chunks of at most 30 seconds. The hosted recognition response documents text. Confirm variant and timing detail in a live smoke test. The assignment also permits self-hosted Bodhan weights. [Bodhan API reference](https://console.bodhan.ai/api-docs/)
- Provider modules read `BODHAN_TRANSLATE_KEY`, `BODHAN_SPEAK_KEY`, `BODHAN_TRANSCRIBE_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, and `LLM_API_KEY`. The judge uses an OpenAI-compatible client with a JSON schema the harness validates. Exports carry no credentials, provider settings, or dataset state. Automatic failures include non-Bodhan translation, TTS, or recognition, learned quality estimation such as COMET, LLM-authored or corrected Indic text, demo-specific thresholds or rules, and committed secrets. Keep `.env`, generated audio, and caches out of Git.
- The Cookbook asks for a snake_case recipe under `examples/`, pinned `requirements.txt`, a placeholder-only `.env.example`, a `.gitignore`, `sample_data/`, ignored `outputs/`, and a README with `Setup` and `Run`. Its validator looks for `BODHAN_API_KEY` in `.env.example`. Keep an empty template placeholder and read the six assignment variables at runtime. Run the recipe tests explicitly because `make check` invokes pytest on root `tests/`. Run the recipe validator and `make check` before submission. The assignment supplies the specific branch and PR title. ## Reproducible reports and runtime telemetry

Put evidence, coverage and skip decisions, metrics, thresholds, input and config fingerprints, and the **original evaluation cost** in the stable report. Serialize with stable ordering, UTF-8, and consistent newlines. Persist the original usage ledger, priced by model and operation, with the evidence. Use provider-reported usage or documented units and a versioned rate table. Mark estimates, unknown LLM tariffs, and unknown billing explicitly. Bodhan documents ₹0.20 per 10,000 translation output tokens, ₹6 per 10,000 synthesis input characters, and ₹0.10 per audio minute. [Bodhan pricing](https://console.bodhan.ai/#pricing)

Emit **current invocation spend** and model calls, including chargeable retries, in structured runtime telemetry alongside elapsed time, timestamps, cache hits, and request IDs. Write telemetry outside the stable report files. A complete cache replay must show zero provider calls and ₹0 in incremental model cost, while its report retains the original cost and identical bytes. Use an exact-input cache keyed by provider, model, operation, payload, settings, and relevant prompt version, hashing the actual audio bytes. Persist completed run decisions so a replay reproduces budget-related skips as well as successful work. New executions reserve costs atomically before dispatch and use bounded concurrency, backoff and retry rules. The scope of `--max-cost-inr` for unpriced judge calls needs confirmation before a live run.
